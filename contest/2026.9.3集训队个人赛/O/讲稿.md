## 第 1 页 · 封面

大家好！今天分享个人赛 O 题 Xor Triangle，也叫"异或三角形"。这道题代码只有二十行，核心是一条公式：
4^N 减 3^(N+1) 加 3 乘 2^N 再减 1。听上去像背答案，其实整个推导只用到一个四行的小表和异或的两个基本性质。
我会把每一步"为什么这么想"讲清楚，最后再聊两个容易翻车的细节。

## 第 2 页 · 题意

先读题：给定 N，统计满足 1 ≤ a,b < 2^N 的有序整数对 (a,b) 有多少个，使得 a、b、a 异或 b 这三个数能构成非退化三角形，
答案对 998244353 取模。注意三点：整数对是有序的，(a,b) 和 (b,a) 算两个；N 可以到 10 的 18 次方，
所以枚举 4^N 对不可能，按位 DP 也至少 O(N)，必须推闭式公式；
另外条件完全由 a、b 的二进制位决定，说明这本质上是一道位运算计数题，不是几何题。

## 第 3 页 · 关键观察：a + b ≥ a ⊕ b（四种位情况）

先看一个最简单的观察：任意两个数的和，一定大于等于它们的异或。为什么？逐位看四种情况，做一个四行的小表：
00 时，和是 0，异或也是 0，相等；01 时，和是 1，异或也是 1，相等；10 时同理，相等；
只有 11 这一行不一样——和是 2，进了一位，而异或是 0，和严格大于异或。
所以 a+b 大于等于 a 异或 b：取等当且仅当没有任何一个 11 位，也就是 a&b 等于 0；
严格大于当且仅当至少有一位是 11，也就是 a&b 不等于 0。
等价地，有个恒等式 a+b 等于 a⊕b 加 2 倍的 a&b。这把"和与异或谁大"的问题完全归结到 a&b 上。

（板书建议：把 00/01/10/11 四行小表画出来，圈出 11 那一行，后面所有推导都在用这张表。）

## 第 4 页 · 异或的性质：做两次相同运算无效果

再看异或的一个基本性质：同一个数异或两次，等于没做，x 异或 y 再异或 y 等于 x。
应用到本题：c 等于 a 异或 b，两边同时异或 b，得到 a 等于 b 异或 c；同时异或 a，得到 b 等于 a 异或 c。
也就是说，三个数两两之间都能通过异或互相转化，(a,b)、(b,c)、(a,c) 三组地位完全对等。
于是我们不需要先弄清楚三条边谁最长——直接列出三条三角形不等式 a+b>c、b+c>a、a+c>b，
每一条都用同一招判断：对应的两个数是否至少有一位 11。

## 第 5 页 · 转化：三条不等式 → 三个位条件

现在把三条不等式逐条翻译。第一条 a+b 大于 c：由小表，等价于 (a,b) 至少有一位 11，也就是 a&b 非零。
第二条 b+c 大于 a：注意 b 异或 c 恰好等于 a，所以等价于 (b,c) 至少有一位 11，也就是 b&c 非零。
怎么把 b&c 换成只关于 a、b 的条件？逐位看：c 的每一位是 a 和 b 异或出来的，b 和 c 同时为 1，
当且仅当 b 这一位是 1 而 a 这一位是 0——所以 b&c 就是"b 里有、a 里没有"的那些位。
b&c 非零，等价于 b 不是 a 的按位子集。第三条完全对称：a&c 非零，等价于 a 不是 b 的子集。
于是非退化等价于三个位条件：a&b 非零，b 不包含于 a，a 不包含于 b。到这里"三角形"彻底消失，
问题变成三个纯位运算条件的计数。

## 第 6 页 · 反向入手：三个坏事件 A、B、C

接下来怎么数？非退化要求三个"非"条件同时成立，直接数不好数——三个条件互相纠缠，凑在一起没有整齐的结构。
所以我们反向入手，数不满足的，也就是坏对。每个坏条件单看都很简单，就是"某两个数没有 11 位"。
定义三个坏事件集合：A 表示 a&b 等于 0；B 表示 b 包含于 a，也就是 b&c 等于 0；C 表示 a 包含于 b，也就是 a&c 等于 0。
答案就是全体减去 A、B、C 的并集。另外先说一个小技巧：我们把 a、b 的取值先放宽到 0 到 2^N 减 1、允许取 0——
这样每个集合的计数会变得非常整齐，最后再说明 0 不影响答案。

## 第 7 页 · 容斥：维恩图（先含 0 计数）

画个维恩图。含 0 的情况下，三个集合的计数完全对称：每个集合大小都是 3^N——比如 A，每个 bit 三种去向：
只在 a、只在 b、都不在，3^N 种；因为 0 是合法的，不需要挖任何东西。两两交集都是 2^N：
比如 A 交 B，a&b 为 0 又要求 b 包含于 a，只能 b 等于 0，a 随便取，2^N 种；B 交 C 是 a 等于 b，也是 2^N 种。
三元交集只有 1 对：a 等于 b 等于 0。代入容斥公式：三个 3^N 相加，减去三个 2^N，加回 1，
并集等于 3 乘 3^N 减 3 乘 2^N 加 1。

## 第 8 页 · 0 无影响 + 最终公式

最后处理 0。题目真实要求 a、b 从 1 开始，但我们刚才是从 0 开始数的。
观察：a 等于 0 或者 b 等于 0 的对，按位与一定为 0，全部落在 A 里，全是坏对。
也就是说，放宽到含 0 之后多算进来的对，全部会在容斥里被减掉——好对的数量两个版本完全一样，所以 0 没有影响。
全体 (2^N)² 等于 4^N，减去并集，得到最终答案：4^N 减 3^(N+1) 加 3 乘 2^N 减 1。

## 第 9 页 · 样例核对

用官方样例核对：N=2 答案是 0；N=5 是 390——比如 (13,24)，13 异或 24 等于 21，
13+24 大于 21、13+21 大于 24、21+24 大于 13，确实构成三角形；N=10000 是 851087540。
三个样例与公式、代码输出全部一致。

## 第 10 页 · 代码实现

代码二十行：快速幂分别算 2^N、3^(N+1)、4^N 三个幂次，然后套公式输出。
三个细节：一是三次快速幂，时间 O(log N)、空间 O(1)，10 的 18 次方也没压力；
二是减法先加 MOD 再取模，防止 C++ 里负数取模得到负数；
三是乘法不会爆：998244353 的平方大约是 9.96 乘 10 的 17 次方，小于 long long 上限 9.2 乘 10 的 18 次方。

## 第 11 页 · 总结

总结一下套路链：先用四行小表把"和与异或谁大"归结到 a&b 是否为 0；
再用异或自反性把三条三角形不等式统一翻译成三个位条件；正面数"三个条件同时成立"太纠缠，
就反向数三个坏事件 A、B、C，用容斥相减；计数时先含 0 让集合完全对称，最后验证 0 无影响；
得到闭式公式后用快速幂 O(log N) 求值。
三个可迁移的点：第一，比较"和"与"异或"，永远先列 00/01/10/11 小表，答案全在表里；
第二，x 异或 y 异或 y 等于 x 让三组对等，避免先比谁最长；
第三，正面难数就反向容斥，"含 0 再验证无影响"是让计数变整齐的常用技巧。
最后送一个彩蛋：合法三角形一定三边互异——a 等于 b 会推出 c 等于 0，
所以 N 等于 1、2 时答案是 0 并不奇怪。谢谢大家，欢迎提问。

### 可能的提问 & 应对

- **"三角形不是还要『两边之差小于第三边』吗？为什么只列三条『和 > 第三边』？"**
  三边都是正数时，三条"两边之和大于第三边"与"两边之差小于第三边"是等价的：
  比如 a+c > b 和 b+c > a 两式相减，就得到 c > |a−b|。所以标准判定就是三条和不等式，一条都不少、也一条都不多。
  而且这三条不等式在我们的模型里**天然不会出现"和 < 第三边"**：小表保证 a+b ≥ a⊕b 恒成立，而 a⊕b 恰好是 c；
  由自反性又有 b⊕c = a、a⊕c = b，所以三条"和 ≥ 第三边"恒成立，唯一会失败的是取等（退化）。

- **"为什么 b&c 等于 b&~a？"**
  逐位看：c 的每一位是 cᵢ = aᵢ ⊕ bᵢ。bᵢ 与 cᵢ 同时为 1，当且仅当 bᵢ = 1 且 aᵢ = 0。
  所以 b&c 恰好是"b 里有、a 里没有"的那些位，也就是 b&~a。它非零等价于 b ⊄ a。

- **"为什么含 0 不影响答案？"**
  a = 0 或 b = 0 时，a&b 一定为 0，这类对全部落在坏集合 A 里，容斥时会连同其他坏对一起被减掉。
  所以含 0 版本与不含 0 版本的"好对集合"一模一样，答案不变。
  反过来问"那为什么不干脆从头就用不含 0 的版本"——也可以，但要挖 0：A 挖 a=0、b=0 有交集要加回，
  B、C 不用加回，三个集合变得不对称、容易错。含 0 就是牺牲一点"直观"换"整齐"。

- **"为什么 A∩B 只有 2^N 对？"**
  A 要求 a&b = 0，B 要求 b ⊆ a（b 的每个 1 位都在 a 里）。两个条件合起来，b 的每个 1 位既要在 a 里、
  又不能与 a 重叠，只能 b = 0；此时 a 随便取，共 2^N 种。

- **"如果题面把上界写成 ≤ 2^N（而不是 < 2^N），答案会变吗？"**
  不会。含 2^N 的 (a,b) 全部是坏对：若 a = 2^N、b < 2^N，则 a&b = 0（坏）；
  若 a = b = 2^N，则 a ⊆ b 且 b ⊆ a（坏）。所以 [1, 2^N] 与 [1, 2^N) 两种题面推出同一个公式。
  （QOJ 原题写的是 < 2^N，如果现场版本写 ≤ 2^N 不必紧张。）

- **"N = 1 为什么答案是 0？"**
  a、b 只能取 1，a = b 时 c = 0，构不成三角形；且只有这一种取值。

- **"能不能用 3 进制 DP / 枚举统计？"**
  能推导出同样的计数（每个 bit 三种状态就是 3^N 的来源），但 N 到 10^18，任何 O(N) 的 DP 都超时，
  必须把 3^N 直接用快速幂算——这正是"先推公式再快速幂"的题。
